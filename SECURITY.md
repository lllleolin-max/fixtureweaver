# Security and sensitive data

This is a local fixture utility, not an anonymization/privacy/native-engine sandbox product. Stable masks reveal linkage and can be guessed from known domains/salt. Unmasked fields, pinned protected classes, schema names, consumer results, errors and hash/size receipts can disclose information. A protected occurrence keeps its entire equivalence class in original storage representations.

Use only authorized synthetic/already reviewed test copies; restrict output access and avoid confidential query results in logs. A smaller fixture is not inherently safe to share. There is no differential privacy, anonymity certificate or PII-absence proof.

Require a quiescent DELETE-mode single file with no sidecars. Matching hashes/read-only access are not a concurrent multi-file snapshot service. Fingerprints are byte receipts, not authenticity signatures. Authorizers/bounds do not isolate Python, SQLite, filesystem or host-library defects. Use patched runtimes and external process/container isolation for untrusted databases. This tool loads no native extensions.

Rows/cells/file bytes/string-BLOB-row bytes/observed instructions are bounded. Hashing, Python and filesystem work are outside the SQLite instruction counter. Hard-link publication needs a supporting filesystem and refuses existing destinations, including a concurrent creator.

Report vulnerabilities privately through the maintainer's available GitHub profile contact or repository security-reporting channel when available. Do not send secrets, real personal data or production DBs. Public reports should use synthetic schema/plan, Python/SQLite versions and error code. No response-time commitment is claimed.
