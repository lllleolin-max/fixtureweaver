# FixtureWeaver 中文项目说明

**做什么。** 面向 SQLite 集成测试，从指定种子行补齐外键祖先，将关联标识统一确定性映射，输出独立缩减数据库；最终实际检查外键、唯一约束、完整性及业务查询。

**怎么用。** Python 3.11+、SQLite 3.37+ 环境执行 `python -m pip install .`，然后 `python examples/demo.py --out demo-output`。调用 SDK `weave(source,destination,plan)` 或运行 `fixtureweaver demo-output/checkout.db demo-output/new.db --plan demo-output/plan.json`。输出名称必须全新；演示已占用 `sdk-fixture.db` 与 `cli-fixture.db`。

JSON 的 `seeds` 声明表/SQL 条件/参数，`masks` 声明标识类列，外键相连列自动扩展；`protect` 固定整个等价类原始表示；`queries` 声明精确预期；`limits` 限制行、单元、指令、字节及查询结果。成功返回报告/退出码 0；拒绝返回结构化原因/退出码 2，不发布失败数据库。

**为什么。** 抽样可能丢失订单的账户/租户；逐列替换可能把同一标识改成不同值。测试因外键/联表错误失败，无法验证原业务问题。关系闭包和共享映射一起解决此任务，而不是通用数据合成或匿名化。

**已测结果。** 合成结账库 16 行保留 5 行，增加 3 行依赖，查询保持 `[[120,3,2]]`。普通抽样/独立掩码有 2 个外键错误；只加闭包仍有 4 个。独立账本三种方法均成功；20 行链必须全留。小库文件字节数未减少，不声称成本收益。普通 wheel 安装后的 SDK 与真实注册 CLI 文件哈希一致。测试数量和结果均绑定实际执行的 Git 归档。

**边界。** 支持复合键、NOCASE/亲和性、NULL、循环、自关联、WITHOUT ROWID 和可重建的普通约束/索引/视图。拒绝 WAL/sidecar、触发器、虚拟表、生成列、定制排序规则/函数。要求静止单文件副本；保护值与稳定掩码均保留关联，没有匿名化、差分隐私或安全证明。仅认证本次支持约束和声明查询。

**商业/技术/创新证据。** 潜在使用者是维护 SQLite 测试数据的应用/质量团队；尚无客户、收入、真实成本节省或付费意愿证据。技术依据是 SQLite 真实语义和约束、独立 CTE 预言机、异常边界及五轮可重放纠错。SDV 已支持关系数据、复合键与跨表约束；区别是选行缩减、SQLite 语义、关联掩码、独立库和查询验收的具体组合。没有执行 SDV，也不声称竞品缺少未提及功能。三轴评分由独立审查决定，作者不自评达标。
